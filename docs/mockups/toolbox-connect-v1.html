RIGEL × TOOLBOX — MOCKUP v1

Slice 1: Rigel's brain (Claude or Ollama) can find and run ToolBox tools. Approvals appear as a card you can click or answer out loud. Rigel's own app handlers are unchanged.

1 · Read-only tool, server cold-started

Rigel asks ToolBox need() for matching tools, then runs one with call(). Each step shows up as a small chip under your message. Yellow dot = ToolBox had to start the server first.

ToolBox · 7 servers

2 · Gated tool → approval (click or voice)

osa-system asks for approval through MCP elicitation, and ToolBox forwards that request to Rigel. Rigel shows the card and speaks a one-line summary, then listens for "yes" or "no" without needing the wake word. If you don't answer before the timer runs out, the request is declined.

listening for "yes" / "no"

3 · After the answer, and when ToolBox is down

Every tool step is written to ~/.rigel/rigel.db along with the conversation turn. If ToolBox can't be reached, Rigel says so once and answers without tools. It never fails silently.

ToolBox offline
Youyes
osa-system.fs.delete · approved by voice · 210 ms
RigelDone. old-screenshots is gone.
YouAny new mail from Dana?
ToolBox unreachable at 127.0.0.1:8795
RigelI can't reach ToolBox right now, so I can't check your mail. It may not be running. Try toolbox status.
